# Отчёт о совместимости: дневник на Windows и Linux

**Проект:** `C:\Users\user\Desktop\diary`
**Задача:** приложение должно устанавливаться и работать и на Windows, и на Linux
(сейчас на Windows не работает).
**Дата проверки:** 2026-09-27
**Статус:** выполнено, проверено на Windows 10.0.20348 (x64) и Linux (Debian, WSL2, x86_64).

---

## 1. Что именно падало на Windows

### Наблюдаемый факт (воспроизведено)

Чистое виртуальное окружение, Python 3.12.8, Windows x64:

```
> python -m pip install sqlcipher3-binary
ERROR: Could not find a version that satisfies the requirement sqlcipher3-binary (from versions: none)
ERROR: No matching distribution found for sqlcipher3-binary
EXITCODE=1
```

Следствие в самом приложении: `import sqlcipher3` не срабатывает, срабатывает
`from pysqlcipher3 import dbapi2` — тоже нет, и `TUI.py` печатает

```
Ошибка: не установлен SQLCipher. Установите: pip install sqlcipher3-binary
```

и завершается с кодом 1. На Linux тот же код работал, поэтому проблема не в
логике дневника, а в зависимостях.

### Причина (подтверждена метаданными PyPI)

Опрошен актуальный индекс PyPI (`https://pypi.org/pypi/<пакет>/json`):

| Пакет | Версия | Есть колесо для Windows? |
|---|---|---|
| `sqlcipher3-binary` | 0.6.0 | **нет** — только `cp38…cp314 manylinux2014_x86_64` |
| `sqlcipher3` | 0.6.2 | **да** — `win_amd64`, `win32`, `win_arm64` (cp39–cp314) |
| `sqlcipher3-wheels` | 0.5.7 | да (`win_amd64`), но версия устаревшая |
| `pysqlcipher3` | 1.2.0 | нет — только исходники |
| `apsw` | 3.53.4.0 | колесо есть, но шифрование в них не включено |

`sqlcipher3-binary` — это устаревший пакет «только готовые колёса»: сборки из
исходников он не предлагает, а под Windows колёс не публикует. Поэтому на
Windows он не устанавливается ни при каких условиях.

---

## 2. Выбранное решение

**Драйвер шифрованной SQLite заменён на пакет `sqlcipher3==0.6.2`.**

Почему именно он:

* тот же импортируемый модуль `sqlcipher3` и тот же DB-API — код `TUI.py` почти не меняется;
* готовые колеса и для Windows, и для Linux (и macOS) — установка без компилятора и без OpenSSL SDK;
* тот же формат зашифрованной базы (SQLCipher 4), поэтому **перенос данных не нужен**;
* пакет активно поддерживается, в отличие от `sqlcipher3-binary`.

Зафиксировано в `requirements.txt`:

```
sqlcipher3==0.6.2
windows-curses>=2.3.1 ; sys_platform == "win32"      # curses для полноэкранного режима на Windows
google-api-python-client>=2.100                       # необязательно (синхронизация с Google Drive)
google-auth-oauthlib>=1.1
google-auth-httplib2>=0.2
```

Дополнительно в `TUI.py`:

* порядок импорта `sqlcipher3` → `pysqlcipher3` (очень старые окружения) с понятным
  сообщением об установке вместо упоминания нерабочего пакета;
* фолбэк совместимости: если база создана SQLCipher 3.x, она автоматически
  переоткрывается с `PRAGMA cipher_compatibility = 3/2/1` — старые дневники не теряются;
* `PRAGMA cipher_log_level = NONE` — SQLCipher больше не печатает свои отладочные
  сообщения в stdout и не ломает машиночитаемый вывод;
* путь к базе переопределяется переменной `DIARY_DB` (нужно для переноса и тестов);
* `notepad` как редактор по умолчанию на Windows и включение ANSI-цветов в консоли Windows.

### Рассмотренные и отклонённые варианты

| Вариант | Почему отклонён |
|---|---|
| Сборка `sqlcipher3`/`pysqlcipher3` из исходников на Windows | нужен MSVC + OpenSSL + SQLCipher SDK, долго и хрупко; готовое колесо уже есть |
| `sqlcipher3-wheels` 0.5.7 | есть Windows-колесо, но версия старее и проект менее живой |
| `apsw` | в колесах с PyPI шифрование не скомпилировано |
| Обычный `sqlite3` без шифрования | снижает защиту личных данных — по условиям задачи требует отдельного согласия пользователя |
| Прикладное шифрование поверх обычного SQLite | меняет формат базы → существующие записи потребовали бы миграции и риска потери |

### 4.6 Существующая база пользователя

Файл `C:\Users\user\Desktop\diary\.diary.db` (20480 байт, кратно 4096 — 5 страниц):

* первые байты не `SQLite format 3` → файл зашифрован;
* обычный `sqlite3` его не читает: `file is not a database`;
* `sqlcipher3` с произвольным паролем тоже отказывается (`hmac check failed`) →
  это действительно база SQLCipher, а не что-то другое;
* резервная копия побайтово идентична исходнику (SHA-256
  `EA217283D59C18C1477F8C94E7748209A127C7BAB39248EE38C168DF766D3122`).

> покажет число записей и `integrity_check`. Совместимость формата проверена на

## 5. Компромиссы и ограничения

1. **Зависимость от `sqlcipher3` 0.6.x.** Версия зафиксирована точно (`==0.6.2`),
   чтобы сборка была воспроизводимой. При обновлении стоит перепроверять тесты.
2. **`requirements.txt` тянет Google API (~16 МБ).** Это сохранение прежнего
   поведения; если синхронизация не нужна, эти три строки можно удалить —
   приложение продолжит работать.
3. **Резервная копия делается через `VACUUM INTO`** — файл получается согласованным
   и зашифрованным, но не побайтово равным исходнику (новый salt). Если нужен
   именно побайтовый снимок — используйте копирование файла (фолбэк встроен).
4. **CI на GitHub не запускался** — репозитория на GitHub у проекта нет.
   Файл `.github/workflows/ci.yml` готов; после `git remote add` + `push` матрица
   заработает. Эквивалент прогона локально — `scripts/selfcheck.py` (на обеих ОС
   даёт 22/22).
5. **Проверка TUI на Windows выполнялась в ConPTY**, а не в классической консоли
   `conhost.exe`. На Windows 10/11 в Windows Terminal всё работает так же;
   в старом `cmd.exe` возможны проблемы с эмодзи — лечится `chcp 65001`.
6. **Linux проверялся в WSL2 (Debian, glibc 2.41)**, а не на «голом» железе.
   Использованные колеса — manylinux, то есть переносимые на обычные дистрибутивы.

## 6. План отката

```powershell
# Windows: вернуть исходный скрипт
Copy-Item .\TUI.py.orig .\TUI.py -Force
```
```bash
# Linux
cp TUI.py.orig TUI.py
```

Затем в `requirements.txt` заменить `sqlcipher3==0.6.2` обратно на
`sqlcipher3-binary` (снова сломает Windows, поэтому только как временная мера) и
переустановить зависимости (`install.ps1` / `install.sh`).

Файл базы откатывать не нужно — формат не менялся, база читается и старой, и
новой версией. Если что-то пошло не так, восстановите её из резервной копии:

```powershell
.\run.ps1 backup "diary-backup.db"     # до изменений
Copy-Item "diary-backup.db" "$env:USERPROFILE\.diary.db" -Force   # при необходимости
```

Удалить созданное окружение: `Remove-Item .venv -Recurse -Force` (Windows),
`rm -rf .venv` (Linux).
